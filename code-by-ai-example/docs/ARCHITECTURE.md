# Архитектура: Quiz API

> Этот документ отвечает на вопрос «как строим». Если нужного решения здесь нет, агент спрашивает, а не выбирает сам.

## Стек

| Назначение | Выбор |
|---|---|
| Язык | Python 3.12 |
| Веб-фреймворк | FastAPI, Pydantic v2 |
| База данных | SQLite через aiosqlite |
| ORM и миграции | SQLAlchemy 2 (async), Alembic |
| Настройки | pydantic-settings |
| Тесты | pytest, pytest-asyncio, httpx (`AsyncClient`) |
| Качество кода | ruff, mypy (strict) |

Новые зависимости добавляются только после согласования.

## Структура проекта

```text
app/
  main.py          # создание приложения, подключение роутеров и обработчиков ошибок
  core/            # config.py, errors.py, security.py
  db/              # движок, сессии, базовый класс моделей
  models/          # модели SQLAlchemy
  schemas/         # схемы Pydantic для запросов и ответов
  repositories/    # запросы к базе данных
  services/        # бизнес-правила
  api/v1/          # роутеры
migrations/        # миграции Alembic
tests/             # тесты через HTTP API, по файлу на группу эндпоинтов
```

## Правила слоёв

Зависимости идут только в одну сторону: `api → services → repositories → models`.

| Слой | Отвечает за | Не должен |
|---|---|---|
| `api` | HTTP: разбор запроса, код ответа, зависимости | Содержать бизнес-правила и обращаться к базе |
| `services` | Бизнес-правила, границы транзакций | Знать о HTTP и возвращать схемы ответа |
| `repositories` | Запросы к базе | Содержать бизнес-правила и фиксировать транзакции |

## Модель данных

```text
Quiz          id, title, description, is_published, created_at
Question      id, quiz_id → Quiz, text, position
Option        id, question_id → Question, text, is_correct, position
Attempt       id, quiz_id → Quiz, player_name, score, max_score, created_at
AttemptAnswer id, attempt_id → Attempt, question_id → Question, option_id → Option
```

- Все даты хранятся в UTC и отдаются в формате ISO 8601.
- `Attempt` хранит `score` и `max_score`, чтобы таблица лидеров не пересчитывала результаты.
- Индекс `(quiz_id, score DESC, created_at ASC)` на `Attempt` обслуживает таблицу лидеров.

## Ошибки

- `AppError` в `core/errors.py` содержит `status_code`, `code` и `message`. Для каждой ошибки из `SPEC.md` есть свой наследник.
- Общий обработчик приводит `AppError` и ошибки валидации FastAPI к единому формату.

## Тестирование

- Каждый тест получает чистую базу SQLite в памяти.
- Тесты обращаются к приложению через `httpx.AsyncClient`, поэтому проверяют маршруты, схемы и базу вместе.
- Имя теста описывает поведение и ссылается на правило, если оно есть: `test_r8_missing_answer_returns_422`.

## Журнал решений

Здесь записано, почему выбран тот или иной вариант, чтобы следующие сессии не пересматривали решение без причины.

| Дата | Решение | Причина | Отвергнутый вариант |
|---|---|---|---|
| 2026-11-01 | SQLite | Для MVP достаточно, ничего не нужно разворачивать | PostgreSQL: добавляется, когда понадобится |
| 2026-11-01 | Все ответы отправляются одним запросом | Не нужно хранить незавершённые попытки | Пошаговое прохождение: усложняет модель |
| 2026-11-01 | Ключ автора вместо учётных записей | В MVP один автор | JWT: избыточно для одного автора |
