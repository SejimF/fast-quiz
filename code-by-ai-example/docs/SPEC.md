# Спецификация: Quiz API

> Этот документ отвечает на вопрос «что строим». Каждое правило сформулировано так, чтобы по нему можно было написать тест.

## 1. Цель

Дать автору простой способ публиковать викторины через API, а игрокам возможность проходить их без регистрации и сравнивать результаты.

**Критерий успеха MVP:** автор создаёт и публикует викторину, игрок проходит её и видит свой результат и таблицу лидеров. Весь сценарий покрыт автоматическим тестом.

## 2. Роли

| Роль | Как определяется | Что может |
|---|---|---|
| Автор | Заголовок `X-Admin-Key` совпадает с `ADMIN_API_KEY` | Создавать и публиковать викторины |
| Игрок | Без аутентификации, указывает только имя | Смотреть опубликованные викторины, проходить их, смотреть результаты |

## 3. Основные сценарии

1. Автор отправляет викторину с вопросами и получает её в статусе черновика.
2. Автор публикует викторину.
3. Игрок видит список викторин и открывает одну из них. Правильные ответы ему не показываются.
4. Игрок отправляет все ответы одним запросом и сразу получает результат.
5. Любой пользователь смотрит таблицу лидеров викторины.

## 4. API

Базовый путь: `/api/v1`. Формат данных: JSON.

| Метод и путь | Доступ | Успех | Описание |
|---|---|---|---|
| `GET /health` (без базового пути) | Все | 200 | Возвращает `{"status": "ok"}` |
| `POST /quizzes` | Автор | 201 | Создать черновик вместе с вопросами |
| `POST /quizzes/{id}/publish` | Автор | 200 | Опубликовать викторину |
| `GET /quizzes?limit=20&offset=0` | Все | 200 | Список опубликованных викторин |
| `GET /quizzes/{id}` | Все | 200 | Викторина с вопросами, без правильных ответов |
| `POST /quizzes/{id}/attempts` | Все | 201 | Отправить ответы и получить результат |
| `GET /attempts/{id}` | Все | 200 | Посмотреть результат попытки |
| `GET /quizzes/{id}/leaderboard` | Все | 200 | Первые 10 результатов |

### Пример: создание викторины

```http
POST /api/v1/quizzes
X-Admin-Key: <key>

{
  "title": "Основы Python",
  "description": "Короткий тест",
  "questions": [
    {
      "text": "Что вернёт len('abc')?",
      "options": [
        {"text": "2", "is_correct": false},
        {"text": "3", "is_correct": true}
      ]
    }
  ]
}
```

### Пример: отправка ответов

```http
POST /api/v1/quizzes/1/attempts

{
  "player_name": "Анна",
  "answers": [{"question_id": 1, "option_id": 2}]
}
```

```json
{
  "id": 7,
  "quiz_id": 1,
  "player_name": "Анна",
  "score": 1,
  "max_score": 1,
  "answers": [
    {"question_id": 1, "option_id": 2, "correct_option_id": 2, "is_correct": true}
  ],
  "created_at": "2026-11-01T12:00:00Z"
}
```

## 5. Бизнес-правила

| ID | Правило |
|---|---|
| R1 | После обрезки пробелов длина `title` от 1 до 200 символов. Поле `description` необязательно, до 1000 символов. |
| R2 | В викторине от 1 до 50 вопросов. После обрезки пробелов длина текста вопроса или варианта от 1 до 500 символов. |
| R3 | В каждом вопросе от 2 до 6 вариантов, ровно один из них правильный. |
| R4 | Порядок вопросов и вариантов в ответах API совпадает с порядком при создании. |
| R5 | Черновик для публичных эндпоинтов не существует: ответ `404 quiz_not_found`. |
| R6 | Повторная публикация не считается ошибкой: ответ 200, состояние не меняется. |
| R7 | Публичные `GET /quizzes` и `GET /quizzes/{id}` никогда не возвращают правильные ответы. |
| R8 | Попытка содержит ровно по одному ответу на каждый вопрос викторины. Лишние, пропущенные и повторные ответы дают `422 invalid_answers`. |
| R9 | Выбранный вариант должен принадлежать своему вопросу. Иначе `422 invalid_answers`. |
| R10 | `score` равен числу правильных ответов, `max_score` равен числу вопросов. Счёт вычисляется только на сервере. |
| R11 | После обрезки пробелов длина `player_name` от 1 до 50 символов. |
| R12 | Один игрок может проходить викторину сколько угодно раз. Каждая попытка отдельно попадает в таблицу лидеров. |
| R13 | Таблица лидеров сортируется по `score` по убыванию, при равенстве раньше идёт более ранняя попытка. |
| R14 | `limit` от 1 до 100, по умолчанию 20. `offset` не меньше 0. Список отсортирован от новых викторин к старым. |
| R15 | Ключ автора сравнивается в постоянное время. Отсутствующий или неверный ключ даёт `401 unauthorized`. |

## 6. Ошибки

Все ошибки, включая ошибки валидации, имеют один формат:

```json
{"error": {"code": "quiz_not_found", "message": "Quiz not found"}}
```

| HTTP | `code` | Когда |
|---|---|---|
| 401 | `unauthorized` | Нет ключа автора или он неверен |
| 404 | `quiz_not_found` | Викторина не найдена или является черновиком для публичного запроса |
| 404 | `attempt_not_found` | Попытка не найдена |
| 422 | `validation_error` | Запрос не прошёл валидацию схемы или правил R1–R3, R11, R14 |
| 422 | `invalid_answers` | Нарушены правила R8 или R9 |

## 7. Нефункциональные требования

- Настройки задаются только через переменные окружения, пример находится в `.env.example`.
- Секреты и текст ключа не попадают в логи.
- Автоматическая документация OpenAPI доступна по `/docs`.

## 8. Не входит в MVP

Не реализовывать без отдельного решения:

- регистрацию и учётные записи игроков;
- редактирование и удаление викторин;
- вопросы с несколькими правильными ответами и таймер;
- веб-интерфейс;
- кэширование и ограничение числа запросов.
