# TASK-003: Вопросы и справочники

## Зачем

Автор создаёт вопросы трёх типов, а система не даёт сохранить некорректный вопрос.

## Контекст

`docs/SPEC.md`: раздел 3 (`categories`, `tags`, `questions`, `question_options`, `question_text_answers`, `question_tags`, «Правила целостности»), раздел 4 (модули `catalog` и `questions`, пример создания вопроса, «Проверка текстовых ответов»: функция `normalize`), раздел 7 (страницы `/questions`, `/questions/new` и `/questions/:id`).

## Что сделать

- Миграция для этих таблиц с расширениями `pg_trgm` и `fuzzystrmatch` и индексами из раздела 3.
- `catalog`: `GET /categories?q=`, `POST /categories` с дедупликацией по slug, `GET /tags?q=`. Тэги создаются при сохранении вопроса.
- `questions`: `GET /questions/mine` с фильтрами `type`, `category`, `tag` и `q`, `POST /questions`, `GET`, `PATCH` и `DELETE` для `/questions/{id}`. Изменять вопрос может только автор.
- Чистые функции `slugify` и `normalize` (раздел 4).
- Фронт: таблица «Мои вопросы» с фильтрами, редактор вопроса: выбор типа, варианты с переключателем верности или список допустимых ответов, комбобокс категории с пунктом «Создать “…”», поле тэгов с автодополнением.

## Критерии приёмки

- [ ] **AC1.** `single` с двумя верными вариантами, `single` или `multiple` меньше чем с двумя вариантами, `multiple` без верного варианта и `text` без допустимых ответов отклоняются с `VALIDATION_ERROR`.
- [ ] **AC2.** Создание категории «  Базы  данных » при существующей «базы данных» возвращает существующую категорию.
- [ ] **AC3.** У `text` для каждого допустимого ответа сохраняется `normalized` = `normalize(answer)`.
- [ ] **AC4.** Чужой вопрос нельзя прочитать через `/questions/{id}`, изменить или удалить: ответ `FORBIDDEN` или `NOT_FOUND`. Выбор нужно записать в `docs/decisions.md`.
- [ ] **AC5.** Фильтры `/questions/mine` работают по отдельности и вместе, `q` ищет по тексту.
- [ ] **AC6.** Вопрос, который не использовался в комнате, удаляется полностью. Мягкое удаление проверяется в TASK-008.
- [ ] **AC8.** Вопрос, категории и автодополнение кэшируются по `docs/cache.md`. Повторное чтение не обращается к базе. После `PATCH` или `DELETE` возвращаются новые данные. Списки «Мои вопросы» сбрасываются через увеличение версии.
- [ ] **AC7.** Фронт: нельзя отправить форму `single` с двумя верными вариантами, ошибки бэкенда показываются у полей.

## Тесты в порядке написания (TDD)

1. `unit`: `slugify` (пробелы, регистр, ё→е).
2. `unit`: `normalize` (NFKC, регистр, ё→е, пробелы, пунктуация по краям).
3. `unit`: валидатор правил целостности для каждого типа вопроса.
4. `integration`: дедупликация категорий, автодополнение категорий и тэгов.
5. `integration`: CRUD вопросов, права автора, фильтры.
6. `integration`: кэш вопроса и списков (6 тестов из раздела «Тесты» `docs/cache.md`).
7. `vitest`: редактор вопроса переключает поля по типу и блокирует некорректную отправку.

## Граничные случаи

- Текст вопроса длиннее 2000 символов отклоняется. Тэг длиной 1–32 символа приводится к нижнему регистру.
- `PATCH`, который меняет тип вопроса, проверяется по правилам нового типа.

## Вне области этапа

- Публикация и библиотека (TASK-005), тесты (TASK-004).

## Как проверить вручную

Создать в редакторе вопросы трёх типов, создать категорию с другим регистром и пробелами и убедиться, что дубль не появился.
