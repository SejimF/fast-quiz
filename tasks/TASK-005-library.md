# TASK-005: Публичная библиотека

## Зачем

Пользователи делятся вопросами и собирают тесты из чужих вопросов.

## Контекст

`docs/SPEC.md`: раздел 3 («Правила целостности»: публикация и копирование, `source_question_id`), раздел 4 (`publish`, `unpublish`, `/library/questions`, `copy`), раздел 7 (страница `/library`), раздел 8 («Безопасность»: библиотека скрывает верные ответы).

## Что сделать

- `POST /questions/{id}/publish` и `/unpublish`.
- `GET /library/questions`: фильтры `category`, `tags[]`, `q` (поиск через pg_trgm), `sort`, курсорная пагинация. Доступно и гостю.
- `POST /library/questions/{id}/copy` с необязательным `quiz_id`.
- Отдельная схема `QuestionPublic` без полей верности.
- Фронт: страница `/library` с фильтрами и бесконечной прокруткой, «Добавить в тест», кнопка «Из библиотеки» в конструкторе.

## Критерии приёмки

- [ ] **AC1.** Вопрос без категории нельзя опубликовать: ответ `VALIDATION_ERROR`.
- [ ] **AC2.** В ответе `/library/questions` нет `is_correct`, допустимых текстовых ответов и `text_check`. Тест проверяет весь JSON рекурсивно.
- [ ] **AC3.** В библиотеке видны только опубликованные и не удалённые вопросы. После `unpublish` вопрос из неё пропадает.
- [ ] **AC4.** Фильтры по категории и тэгам (вопрос должен содержать все указанные тэги) и поиск работают по отдельности и вместе.
- [ ] **AC5.** Курсорная пагинация возвращает все вопросы без дублей и пропусков, даже если между запросами страниц добавлены новые вопросы.
- [ ] **AC6.** Копия принадлежит текущему пользователю, хранит `source_question_id`, содержит варианты и верные ответы и не является публичной. С `quiz_id` копия сразу добавляется в конец своего теста. Чужой `quiz_id` даёт ошибку.
- [ ] **AC8.** Страницы библиотеки кэшируются как списки id с версией `lib:ver`. Публикация, снятие с публикации и изменение публичного вопроса делают старые страницы недоступными. В ключах `q:{id}:public` нет полей правильности: проверяется содержимое Redis.
- [ ] **AC7.** Свой вопрос копировать не нужно. Ответ должен быть явным: ошибка или возврат того же вопроса. Выбор нужно записать в `docs/decisions.md`.

## Тесты в порядке написания (TDD)

1. `integration`: publish и unpublish, требование категории.
2. `integration`: в ответе библиотеки нет полей верности (рекурсивная проверка ключей).
3. `integration`: фильтры, поиск, курсорная пагинация.
4. `integration`: копирование без `quiz_id` и с ним, права.
5. `integration`: кэш библиотеки, увеличение версии, отсутствие правильных ответов в Redis.
6. `vitest`: фильтры библиотеки формируют правильные параметры запроса.

## Граничные случаи

- Правка или удаление оригинала после копирования не меняет копию.

## Вне области этапа

- Рейтинг и популярность вопросов.

## Как проверить вручную

Опубликовать вопрос под одним пользователем, найти его в `/library` под другим, скопировать в свой тест. Во вкладке Network убедиться, что в ответе нет `is_correct`.
