# TASK-006: Основа realtime

## Зачем

Подготовить надёжную доставку событий, на которой строятся лобби и игра.

## Контекст

`docs/SPEC.md`: раздел 5 целиком (подключение, каналы, формат событий, синхронизация времени, переподключение, конфиг v6), раздел 4 (модуль `realtime`, `/auth/centrifugo-token`), раздел 7 («Работа с realtime»), раздел 8 («Публикация в Centrifugo — после коммита»).

## Что сделать

- Модуль `realtime`: клиент server API Centrifugo (publish, broadcast, disconnect), конверт события `{type, seq, server_time, data}`, публикация после коммита транзакции.
- `GET /auth/centrifugo-token`: HS256, `sub = user_id`, срок жизни 10 минут.
- Механизм токена подписки на канал. Сам эндпоинт `/rooms/{id}/subscription-token` появится в TASK-007.
- Отладочный эндпоинт, который отправляет тестовое событие в личный канал текущего пользователя. Он доступен только при `DEBUG=true`.
- Фронт: хуки `useCentrifuge`, `usePersonalChannel` и `useServerClock`.
- Ключи конфига Centrifugo нужно сверить с документацией установленной v6.

## Критерии приёмки

- [ ] **AC1.** Токен подключения содержит `sub` текущего пользователя и `exp` через 10 минут и подписан `CENTRIFUGO_TOKEN_SECRET`.
- [ ] **AC2.** Событие из отладочного эндпоинта приходит в `personal:#<user_id>` залогиненного пользователя, а другой пользователь подписаться на чужой личный канал не может.
- [ ] **AC3.** Если транзакция откатилась, событие не публикуется. Если публикация не удалась, это логируется, а запрос всё равно завершается успешно.
- [ ] **AC4.** `useServerClock` вычисляет смещение `server_time − Date.now()` и выдаёт оставшееся время до дедлайна с учётом этого смещения.
- [ ] **AC5.** После неудачного восстановления соединения (`wasRecovering && !recovered`) хук сбрасывает кэш, чтобы данные загрузились заново.

## Тесты в порядке написания (TDD)

1. `unit`: выпуск токена подключения и токена подписки (claims, срок жизни) с подменёнными часами.
2. `unit`: конверт события и `seq`, который растёт монотонно.
3. `integration`: публикация после коммита и отсутствие публикации при откате. Server API подменён записывающим клиентом.
4. `integration`: ошибка Centrifugo не ломает запрос.
5. `vitest`: `useServerClock` с подменённым `Date.now`.
6. `vitest`: обработчик неудачного восстановления вызывает `invalidateQueries`.
7. Проверка вручную или в e2e: событие доходит до браузера (AC2).

## Граничные случаи

- Токен истёк во время соединения: SDK получает новый через `getToken`.

## Вне области этапа

- Канал `room:` и события лобби и игры (TASK-007, TASK-008).

## Как проверить вручную

Войти в систему, открыть консоль браузера, вызвать отладочный эндпоинт и увидеть событие. Под вторым пользователем то же событие приходить не должно.
