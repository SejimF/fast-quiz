# TASK-008: Игровой движок

## Зачем

Ядро продукта: синхронные раунды, честная проверка и подсчёт очков на сервере.

## Контекст

`docs/SPEC.md`: раздел 3 (`room_rounds`, `answers`, мягкое удаление вопросов), раздел 4 (проверка текстовых ответов, `/rooms/{id}/rounds/{index}/answer`), раздел 5 (события `round.*`, `answer.accepted` и `game.finished`), раздел 6 целиком (цикл раунда, подсчёт очков, крайние случаи), раздел 8 («Корректность и конкурентность»).

## Что сделать

- Миграция для `room_rounds` и `answers`.
- `game/checker.py`: проверка ответов `single`, `multiple` и `text` с нечётким сравнением.
- `game/scoring.py`: формула из раздела 6 и рейтинг.
- Сервис `game`:
  - старт раундов после обратного отсчёта со снимком вопроса и одинаковым для всех перемешиванием вариантов;
  - приём ответа одной транзакцией с `FOR UPDATE` и допуском 300 мс;
  - идемпотентное закрытие раунда;
  - финальные `final_score` и `final_rank`.
- `workers/round_timer.py`: каждые 250 мс выбирает просроченные раунды через `FOR UPDATE SKIP LOCKED`.
- Мягкое удаление вопроса, который уже использовался в комнате.
- Фронт: экран раунда (таймер, три типа ввода, «Ответ принят за N с», «Ответили X из Y», подсветка после `round.ended`) и обратный отсчёт.

## Критерии приёмки

- [ ] **AC1.** Очки считаются по формуле из раздела 6. Пример из ТЗ (P = 1000, T = 20, t = 4) даёт 900.
- [ ] **AC2.** Частичный зачёт `multiple` считается как `max(0, (верно − неверно) / всего верных)`.
- [ ] **AC3.** Проверка `text` учитывает `case_sensitive`, нормализацию и расстояние Левенштейна (только для ответов от 5 символов).
- [ ] **AC4.** Второй ответ на тот же раунд даёт `ALREADY_ANSWERED`, в том числе когда два ответа пришли одновременно.
- [ ] **AC5.** Ответ позже `deadline_at + 300 мс` даёт `ROUND_CLOSED`.
- [ ] **AC6.** Раунд закрывается и по дедлайну, и когда ответили все активные игроки онлайн. `round.ended` публикуется ровно один раз.
- [ ] **AC7.** `round.started`, `GET /rooms/{id}` и `answer.accepted` не содержат верных ответов до `round.ended`.
- [ ] **AC8.** Рестарт бэкенда посреди раунда не ломает игру: после запуска воркер закрывает просроченный раунд.
- [ ] **AC9.** После последнего раунда заполняются `final_score` и `final_rank` (при равенстве очков выше тот, у кого меньше суммарное время верных ответов), статус меняется на `finished`, публикуется `game.finished`.
- [ ] **AC11.** Проверка ответа берёт снимок вопроса из `round:{id}:check`, а приём ответа и закрытие раунда остаются транзакциями базы. После `FLUSHALL` посреди раунда игра продолжается правильно.
- [ ] **AC10.** Правка или удаление вопроса после игры не меняет `question_snapshot` прошедших раундов.

## Тесты в порядке написания (TDD)

1. `unit`: `scoring`: формула, границы t = 0 и t = T, округление, рейтинг с равенством очков.
2. `unit`: `checker`: каждый тип, частичный `multiple`, текст с регистром и опечаткой, короткие ответы без нечёткого сравнения.
3. `integration`: приём ответа, `response_time_ms` по серверным часам, `ROUND_CLOSED` с допуском.
4. `integration`: гонка двух одновременных ответов одного игрока.
5. `integration`: гонка закрытия раунда (воркер и «ответили все»): одно событие `round.ended`.
6. `integration`: воркер закрывает просроченный раунд после «рестарта», то есть нового экземпляра сервиса.
7. `integration`: полная игра из трёх раундов с подменёнными часами, итоговые очки и места.
8. `integration`: в ответах и событиях до `round.ended` нет верных ответов (рекурсивная проверка).
9. `integration`: ответ после очистки Redis, снимок раунда в кэше не содержит лишнего в публичных ключах.
10. `vitest`: экран раунда блокирует ввод после отправки и показывает результат по `round.ended`.

## Граничные случаи

Все крайние случаи из раздела 6: потеря соединения, выход во время игры, отключение хоста, выход всех игроков.

## Вне области этапа

- Экран итогов и `/results` (TASK-009).

## Как проверить вручную

Сыграть вдвоём игру из трёх вопросов разных типов. Посреди раунда выполнить `docker-compose restart backend`: раунд должен закрыться по таймеру.
